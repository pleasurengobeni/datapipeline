Filters & Incremental Loading (both optional)


        

          
Filters

          

            Restrict which records are fetched, using date/int columns detected in Step 4. Since every API names its
            own filter query parameters differently, name the exact parameter your API expects — the operator/value
            here are applied as param=value. All filters are combined with AND at runtime.
          

          

          
          
        


        

          
High-Water Mark (incremental loading)

          

            When set, each run only fetches records newer than the last value loaded into the target table — read the
            same way the DB-to-DB job templates do, from the target table itself (never a separate state store).

Column Setup & Cleaning Rules

        

          Columns are auto-detected from your source. For each column you can set the data type,
          click rule chips to choose what cleaning should happen, and optionally rename it in the refined table.
          
🔒 Your actual data values are never sent to the server during detection — only column names.
        


        

          
          
          
        


        
        

          Cleaning rules — click to toggle:  
          Trim removes leading/trailing spaces  | 
          Strip locale tag removes suffixes like [rw-RW]  | 
          Strip separators replaces ,|/-_ with space, keeps first word  | 
          Title Case capitalises each word  | 
          Remove special strips non-alphanumeric chars  | 
          Null if invalid sets -1, numeric-only, <3 chars, or non-alpha-start to NULL  | 
          Empty→NULL treats blank strings as NULL
